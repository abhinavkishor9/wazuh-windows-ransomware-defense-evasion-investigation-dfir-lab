# Ransomware Defense Evasion Investigation with Wazuh (DFIR Lab 55)

## Overview

Ransomware investigations should begin before file encryption occurs. Attackers may first attempt to weaken endpoint defenses, interfere with recovery mechanisms, or stage data for later impact.

In this controlled lab, harmless files were created inside `C:\RansomwareDefenseLab`, a Defender exclusion was added for that directory, Windows recovery configuration and Shadow Copy state were inspected, and the test files were compressed into a harmless archive.

Sysmon, Microsoft Defender Operational logs, Windows process telemetry, and Wazuh were reviewed to investigate the activity.

The lab did not encrypt files, delete Shadow Copies, disable Windows Recovery Environment, or perform destructive ransomware actions.

---

# Lab Objectives

- Establish a pre-investigation endpoint baseline.
- Identify ransomware-style defense-evasion indicators.
- Investigate Microsoft Defender configuration changes.
- Examine recovery and Shadow Copy state.
- Analyze process and network telemetry around the investigation window.
- Distinguish pre-existing security conditions from changes generated by the lab.
- Correlate endpoint evidence with Wazuh.
- Build a pre-encryption incident timeline.
- Avoid interpreting isolated defense-evasion indicators as proof of ransomware.
- Document evidence limitations and the absence of destructive activity.

# Investigation Scenario

A Windows workstation is suspected of exhibiting activity that could precede a ransomware attack.

The analyst identifies several security-relevant conditions:

- Defender configuration changes
- Test data staging
- Recovery configuration state
- Shadow Copy availability
- Process creation activity
- Network connection telemetry

The analyst must determine whether these observations represent an actual ransomware-preparation sequence or controlled/legitimate activity.

# DFIR Analysis

The primary ransomware-style defense-evasion activity directly supported by the evidence is the Microsoft Defender exclusion for `C:\RansomwareDefenseLab`.

The configuration change was captured through Defender Event ID 5007 and can therefore be confidently attributed to the controlled laboratory activity.

The endpoint's Defender baseline is important because several protection features were already disabled before the new exclusion was added. Those states should not be incorrectly interpreted as being caused by the laboratory.

The Recovery Environment was already disabled and no Shadow Copies were present. These findings are useful for ransomware response because they indicate limited recovery capability, but they do not demonstrate that the lab or an attacker intentionally disabled or deleted recovery mechanisms.

The archive operation demonstrates harmless data staging but does not represent encryption or destructive ransomware behavior.

---

# Pre-Encryption Assessment

The controlled lab generated several indicators that would deserve investigation in a real ransomware incident:

```text
Defender Configuration Change
        ↓
Test Data Staging
        ↓
Recovery State Review
        ↓
Process Telemetry
        ↓
Network Telemetry
```

However, the evidence does not establish:

- File encryption
- File renaming at scale
- Shadow Copy deletion
- Recovery Environment modification
- External command-and-control
- Actual ransomware execution

Therefore, the evidence supports a **ransomware defense-evasion simulation**, not a confirmed ransomware infection.

# MITRE ATT&CK Context

The controlled Defender configuration change is relevant to:

Other ransomware investigations may also involve:

- `T1490 – Inhibit System Recovery`
- `T1486 – Data Encrypted for Impact`

Those techniques were not actually performed in this laboratory.

# Outcome

Successfully investigated a controlled ransomware defense-evasion scenario without encrypting data or destroying recovery mechanisms.

The strongest confirmed indicator was the addition of `C:\RansomwareDefenseLab` to Microsoft Defender exclusions, which generated Defender Event ID 5007.

The investigation also demonstrated how pre-existing security conditions, normal background processes, and unrelated network events must be separated from incident-relevant evidence before assessing ransomware risk.
